# АПГРЕЙД — интеграция чат-бота

Документ для команды разработки чат-бота. Описывает точку встраивания виджета и публичные API сайта.

- **Базовый URL:** `https://update.asystem.ai`
- **Авторизация:** не требуется для перечисленных эндпоинтов (они публичные)
- **CORS:** открыт (`Access-Control-Allow-Origin: *`) — можно вызывать с фронтенда
- **Формат:** JSON (`Content-Type: application/json`)

---

## 1. Точка встраивания виджета

Виджет подключается одним файлом:

```html
<script src="/chat-widget.js"></script>
```

Он уже подключён на страницах `index.html`, `media.html`, `system.html`.

Сейчас это **заглушка**: плавающая кнопка справа внизу + мини-окно чата в стиле сайта,
с шаблонными ответами. **Команда бота заменяет содержимое `public/chat-widget.js`**
своим виджетом. Вёрстка, позиционирование и стили уже готовы — можно ориентироваться
на текущий файл как на образец «места».

Фолбэк-канал в заглушке: **WhatsApp менеджера +996 552 180 557** (`https://wa.me/996552180557`).
Рекомендуется оставить аналогичный фолбэк «позвать живого менеджера».

## 2. Чтение данных (GET)

Эндпоинты, которыми бот может отвечать на вопросы о лагере.

### `GET /api/streams`
Список активных потоков с остатком мест.

```json
[
  {
    "id": 1,
    "name": "Поток 1",
    "date_start": "2026-06-20",
    "date_end": "2026-06-30",
    "capacity": 80,
    "price": 19998,
    "spots_left": 80,
    "males": 0,
    "females": 0
  }
]
```

### `GET /api/streams-status`
Занятость по **оплаченным** местам (место считается занятым только при статусе оплаты `paid`).
Квота — 40 мест на каждый пол.

```json
{
  "updated_at": "2026-05-28T12:24:54.035Z",
  "streams": [
    {
      "id": 1,
      "name": "Поток 1",
      "date_start": "2026-06-20",
      "date_end": "2026-06-30",
      "dates": "20 июня – 30 июня",
      "capacity_total": 80,
      "capacity_girls": 40,
      "capacity_boys": 40,
      "paid_total": 0,
      "free_total": 80,
      "percent_total": 0,
      "girls": { "paid": 0, "free": 40, "percent": 0 },
      "boys":  { "paid": 0, "free": 40, "percent": 0 },
      "status": "available"
    }
  ]
}
```
`status`: `available` | `limited` (≤ 20 мест) | `full`.

### Контент (для ответов о лагере)
| Эндпоинт | Что отдаёт |
|---|---|
| `GET /api/admin/public/speakers` | Спикеры |
| `GET /api/admin/public/stars` | Звёзды / амбассадоры |
| `GET /api/admin/public/media` | Галерея медиа |
| `GET /api/admin/champion` | Блок «чемпион» |
| `GET /api/admin/settings/qr` | Картинка QR для оплаты: `{ "value": "<url>" }` |

## 3. Создание заявки — `POST /api/bookings`

Главное «действие» бота: оформить заявку прямо из чата. Заявка попадает в админ-воронку
со статусом `new`.

**Обязательные поля:**

| Поле | Тип | Ограничения |
|---|---|---|
| `stream_id` | number | id потока из `GET /api/streams` |
| `child_name` | string | — |
| `child_age` | number | от **6** до **17** |
| `parent_phone` | string | не короче 9 символов |
| `gender` | string | `"M"` (мальчик) или `"F"` (девочка) |

**Необязательные поля:**
`parent_name`, `parent_city`, `parent_email`, `alt_phone`, `tshirt_size`,
`health`, `allergies`, `about_child`, `wishes`.

> Этот публичный эндпоинт всегда помечает заявку как пришедшую с **сайта** (`source = website`).
> Заявки из Telegram и WhatsApp создавайте через защищённый `POST /api/bot/bookings` (раздел 5),
> чтобы в админке был виден правильный канал.

**Пример запроса:**
```http
POST /api/bookings
Content-Type: application/json

{
  "stream_id": 1,
  "child_name": "Иван Иванов",
  "child_age": 12,
  "parent_phone": "+996555123456",
  "gender": "M",
  "parent_name": "Мария",
  "parent_city": "Бишкек"
}
```

**Ответ 201 (успех):**
```json
{
  "booking_id": 42,
  "qr_image_url": "https://.../uploads/qr/...",
  "message": "Ваша заявка в обработке, с вами в скором времени свяжется менеджер"
}
```

**Ошибки:**
| Код | Причина |
|---|---|
| 400 | не заполнены обязательные поля / неверный возраст / некорректный телефон |
| 404 | поток не найден |
| 409 | мест нет, либо исчерпана квота по полу (40 на каждый пол) |

## 5. Защищённый API бота — `/api/bot/*`

Для заявок из **Telegram и WhatsApp** и для работы с заявками (чтение/изменение).
Все запросы требуют заголовок с ключом:

```http
x-api-key: <BOT_API_KEY>
```

Ключ выдаёт заказчик (хранится в `.env` сайта, в репозиторий не попадает). Без ключа — `401`,
если ключ на сервере не настроен — `503`.

### `POST /api/bot/bookings` — создать заявку из чата
Те же поля, что и в разделе 3, **плюс**:

| Поле | Тип | Значение |
|---|---|---|
| `source` | string | `"telegram"` или `"whatsapp"` (если не указать — `website`) |
| `contact_handle` | string | контакт в мессенджере: `@username` / chat id Telegram и т.п. — чтобы менеджер мог написать первым |

Ответ `201`: `{ "ok": true, "booking": { … } }` (полный объект заявки).

### `GET /api/bot/bookings` — найти заявки
Параметры (любые, можно комбинировать): `phone`, `contact_handle`, `status`, `stream_id`, `limit` (по умолч. 50, макс. 200).
Пример: найти вернувшегося клиента по нику —
`GET /api/bot/bookings?contact_handle=@ivan`

### `GET /api/bot/bookings/:id` — одна заявка
Полный объект со статусом и оплатой (`status`, `payment_status`, `paid_amount`, `base_price`, `discount` …).

### `PATCH /api/bot/bookings/:id` — изменить заявку
Те же поля, что и в админке: `status`, `manager`, `next_action`, `next_contact_date`,
`discount`, `paid_amount`, `payment_date`, `receipt`.
**Статус оплаты считается автоматически** из `base_price`, `discount` и `paid_amount` —
вручную его не задают. Допустимые `status`: `new`, `calling`, `awaiting_payment`, `reserved`, `paid`, `rejected`.

## 6. Что нужно решить со стороны заказчика

- **Бэкенд бота** (сервер бот-команды, ключи LLM) — сайт только хостит виджет и отдаёт данные выше.
- **Ключ `BOT_API_KEY`** — заказчик генерирует и передаёт команде бота по защищённому каналу.
  На сервере (после переезда) ключ нужно **перевыпустить** и не использовать локальный.
